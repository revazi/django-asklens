# Internal semantic decision index

## Status and use

This index maps the accepted semantic decisions implemented by the current
Django 0.2 target to their prose, machine-readable shape, language-neutral
fixture, and focused Django evidence. It records the source tree at
`7776fa03cb741eefab55b725e8343eeb6a7337b6`, immediately before this index was
added.

The index and the five contract documents are **internal, draft, and unfrozen**.
They support review and drift detection for the [AskLens specification](asklens-specification.md).
They are not a public specification, not a compatibility promise, not evidence of
backend neutrality, and not an independent security review. They do not add
serialized versions or authorize a second implementation.

Use the precedence defined by [Draft internal contract schemas](internal-contracts.md):
accepted prose defines semantics, JSON Schema defines wire shape,
language-neutral fixtures provide executable cases, and Django conforms to
those sources. Schema validation is never authorization. If these columns
conflict, stop and resolve the prose decision before changing schema, fixture,
or runtime expectations.

## Evidence notation

Each row has one stable local decision ID:

- **Decision** is the concise accepted rule represented by the row. The linked
  **prose** supplies its fuller internal-contract explanation.
- **Schema** names only the document whose wire shape represents part of the
  rule. **Schema applicability is not semantic coverage.** `—` means the rule is
  contextual or behavioral and cannot be established by standalone shape
  validation.
- **Fixture** names an exact case ID from the [draft internal conformance
  corpus](conformance.md). “No dedicated language-neutral fixture” is explicit. A missing fixture is an
  explicit evidence gap, not proof of a runtime defect.
- **Django evidence** links focused executable tests. The implementation is
  evidence, never the normative source.

Some rows cite a fixture as **supporting** because it executes the behavior but
is not a complete boundary test for that decision. All fixture scenarios receive
identity, permissions, row scope, registration, limits, and clock from the
trusted replay harness; fixture input cannot provide those values.

## Coverage boundaries

The 21 explicit language-neutral cases are representative, not exhaustive.
Notably, DST gap/fold handling, month subtraction, `neq` null behavior, null
ordering, alternate identity validation, to-many cardinality policy, grouped
empty results, presentation, and audit content currently have focused Django
evidence but no dedicated language-neutral fixture. That classification does not
silently authorize new fixtures or expectation changes.

The schemas establish document shape and closure. They cannot by themselves
prove authorization, current request scope, temporal boundaries, database
ordering, relationship cardinality, row/column agreement, decimal
canonicalization, audit effects, or zero application-data SQL. Those properties
require fixture replay and/or implementation tests through the trusted facade.

The corpus is replayed on SQLite and the representative PostgreSQL CI stacks
described in [Draft internal conformance corpus](conformance.md). Passing those
runs does not freeze this index, certify production deployment, establish a
public protocol, or replace application-specific permission and scope tests.
